Parcel Atlas / working implementation

CSV → comparable-rent report

Each property address in an uploaded CSV is matched to a Cotality property ID, validated where necessary, enriched with rental market evidence, then converted into an image-rich HTML report.

InputCSV address column
IdentityCotality property ID
EvidenceLocality rental listings
OutputStandalone HTML report

Detailed batch flow

The process runs independently for every non-empty CSV row. Reports are processed one at a time after the review queue has been resolved, protecting the Cotality sandbox rate limit.

Upload and read CSV

The user uploads a CSV containing one of these headers: address, property address, or full address.

Working now

The browser parses quoted CSV values and creates one queue item for every non-empty address.

Queue item

Original row number and original address text.

Clean and match the address

Each address is sent in parallel to Cotality’s tolerant address matcher and the property suggestion search.

GET /api/corelogic/match?q={address}GET /api/corelogic/search?q={address}

Server routes keep Cotality credentials out of the browser.

Candidate list

Property ID, suggested standard address, and match details where returned.

Make the match decision

The supplied input and each suggestion are normalised before comparison: case, punctuation and common road-type abbreviations are standardised.

Automatic safeguard

Only an exact normalised address match becomes ready automatically. A candidate with a different unit number is never silently accepted.

Ready / review / unmatched

The decision determines whether the property can enter report generation.

Load reference-property evidence

For every ready property ID, the system requests the connected property modules and a comparable-candidate pool.

GET /api/corelogic/properties/{propertyId}GET /api/corelogic/properties/{propertyId}/comparables

Includes attributes, location, advertisements, last sale, imagery and available AVM data.

Reference profile

Address, property configuration, locality ID, images and entitled evidence.

Find comparable rentals

The reference property’s Cotality locality ID drives the rental candidate search. Sale candidates may enrich the pool, but rent evidence is required for the final report.

GET /search/au/property/locality/{localityId}/otmForRentGET /search/au/property/locality/{localityId}/otmForSale

Candidate cards use Cotality address, attributes, rental campaign and image fields when supplied.

Comparable pool

Properties in the same locality, with available rental listing data.

Score, filter and report

Each candidate is ranked against the reference configuration. The final standalone report contains only defensible rental comparisons.

Working now

HTML report includes reference image, comparable images where returned, individual weekly rents, match signals, score breakdown and average weekly rent.

Downloadable report

One self-contained .html file per completed property.

Address-review decision

Exact normalised suggestion

Example: CSV 2 Albert Ave Broadbeach QLD 4218 becomes ready when the returned suggestion is the same address after normalisation. No reviewer action is required.

Ambiguous or different property

Example: CSV 2 Albert Avenue… and suggestion 401/2 Albert Avenue…. It goes to Review because the unit number changes the property identity; the user chooses the correct candidate.

Scoring and report inclusion rules

Scoring is configuration-based. It is not a valuation, and it does not manufacture distance when a usable reference coordinate is absent.

SignalWeightHow it is used
Property type35 pointsRewards the same type, such as unit, house or townhouse.
Bedrooms20 pointsCompares the number of bedrooms with the reference property.
Bathrooms15 pointsCompares the number of bathrooms.
Car spaces10 pointsCompares available vehicle spaces.
Floor or land area10 pointsUses available floor area, or land area where floor area is not returned.
Location10 pointsUses Haversine distance only when both properties have coordinates; otherwise the same-locality fallback is used.
Report filterRequiredCandidate must score at least 60/100 and have a confirmed positive weekly rent. The average is calculated from only these qualifying candidates.
Images

Property and comparable images are URL fields returned by the Cotality imagery/listing responses. They are not base64-encoded or scraped from public websites.

Caching

Property-module responses are cached server-side to reduce repeat upstream calls. A fresh batch report still uses the same entitlement-aware API routes.

Coordinates

Distance is shown only when the reference and candidate records expose usable latitude/longitude. Otherwise the report states that distance is unavailable.

Current scope: this document describes only the implemented CSV → report pipeline. Owner approval, tenant communication, tenant-quality assessment and Property Tree write-back are separate integrations and are intentionally outside this flow.
