01 / upload and validate

A CSV creates a row-by-row worklist.

The file is read in the browser. It must include one address column named address, property address, or full address. Extra columns such as reference_id and report_label are retained in the CSV but are not needed for matching.

Sample CSV input

address,reference_id,report_label
2 Albert Avenue Broadbeach QLD 4218,PROP-001,Broadbeach review
1 Macquarie Street Sydney NSW 2000,PROP-002,Sydney review
120 Collins Street Melbourne VIC 3000,PROP-003,Melbourne review

Validation result

Blank address rows are ignored. If no accepted address-column header exists, the batch stops and displays a format error before any API request occurs.

{
  "rowNumber": 2,
  "originalAddress": "2 Albert Avenue Broadbeach QLD 4218",
  "status": "matching"
}

02 / two address checks, in parallel

Suggestions provide choices. The matcher provides validation.

For each CSV row the browser calls two Parcel Atlas routes in parallel. They authenticate to Cotality on the server; credentials and access tokens never reach the CSV uploader or browser JavaScript.

A. Address Matcher

Browser request. This is a GET request, so it has no JSON body; the address is URL encoded in q.

GET /api/corelogic/match?q=2%20Albert%20Avenue%20Broadbeach%20QLD%204218

Server-side upstream call:

GET /search/au/matcher/address?q={address}&clientName=Parcel%20Atlas
{
  "matchDetails": {
    "propertyId": 47872329,
    "matchType": "E",
    "updateIndicator": "O",
    "parsedAddress": {
      "houseNumber1": "2",
      "streetName": "ALBERT",
      "localityName1": "BROADBEACH",
      "postCode": "4218"
    }
  }
}

B. Suggest API

Browser request. Again this is GET with query text, not JSON body.

GET /api/corelogic/search?q=2%20Albert%20Avenue%20Broadbeach%20QLD%204218

Server-side upstream call:

GET /property/au/v2/suggest.json?q={address}
{
  "suggestions": [
    {
      "propertyId": 47872329,
      "suggestion": "2 Albert Avenue Broadbeach QLD 4218",
      "suggestionType": "PROPERTY"
    }
  ],
  "cacheStatus": "HIT"
}
Authentication detail

Before any Cotality call, the server requests an access token using POST /access/as/token.oauth2 with application/x-www-form-urlencoded client credentials. This token exchange happens only on the server and is not included in browser responses or generated reports.

03 / exact match gate

Only exact suggestions are automatically ready.

The CSV value and each suggestion are compared after normalising case, spaces, punctuation and common street abbreviations such as St → Street. Unit numbers remain significant.

04 / process approved property rows

Two protected routes assemble the report evidence.

The browser runs two approved rows at a time. For each row, it calls the existing property dossier route and the comparable-home route. Both return JSON from server-side Cotality integrations.

Property dossier request

GET /api/corelogic/properties/47872329

Server runs twenty modules in parallel, including core, additional, location, legal, sales, advertisements, AVMs and imagery.

{
  "propertyId": 47872329,
  "successfulModules": 16,
  "totalModules": 20,
  "modules": {
    "core": { "status": 200, "data": { "propertyType": "UNIT", "beds": 1, "baths": 1 } },
    "location": { "status": 200, "data": { "locality": { "id": 3723 } } }
  }
}

Comparable homes request

GET /api/corelogic/properties/47872329/comparables

Server reads the reference locality ID, calls both locality candidate endpoints, deduplicates, pre-scores, enriches the best twelve, then returns final ranks.

{
  "reference": {
    "propertyId": 47872329,
    "localityId": 3723,
    "coordinateAvailable": false
  },
  "candidatePool": { "discovered": 40, "enriched": 12 },
  "candidates": [{ "propertyId": 3314445, "distanceKm": null, "score": { "total": 85 } }]
}
Locality candidate APIs

For reference locality 3723, the server calls GET /search/au/property/locality/3723/otmForSale and GET /search/au/property/locality/3723/otmForRent. Each default first page returns up to 20 summaries. The merged candidate pool is up to 40 records before the 12-record enrichment cap.

05 / rank and generate standalone report

JSON evidence becomes a downloadable HTML file.

The browser renders the report after both protected API responses arrive. No additional external API request is made to generate the HTML; it is composed locally and downloaded as parcel-atlas-{propertyId}.html.

Report contents

  • Reference address, property ID, locality ID and council.
  • Core configuration: type, beds, baths, parking, land and floor area.
  • Property imagery if returned by Cotality.
  • Consumer AVM, rental AVM, last sale and sale date when returned.
  • Every enriched comparable: property ID, configuration, campaign price, area, score and score breakdown.
  • Distance in kilometres when reference and candidate coordinates exist; otherwise an explicit “Same locality” fallback note.
  • Data module coverage and evidence disclaimer.
