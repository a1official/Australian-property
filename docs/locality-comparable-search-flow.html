Parcel Atlas / Technical note

Exact locality in.
Comparable homes out.

A practical record of how Parcel Atlas uses Cotality locality search to discover, enrich and rank comparable Australian properties.

Live example: 2 Albert Avenue, Broadbeach QLD 4218 · Prepared 19 August 2026

01 / resolve the reference property

One property establishes the boundary.

The user selects a validated address. Parcel Atlas loads its CoreLogic location record and reads the nested locality identifier. It does not infer locality from text or postcode.

Location request

Input: validated CoreLogic property ID.

GET /property-details/au/properties/47872329/location
{
  "singleLine": "2 Albert Avenue Broadbeach QLD 4218",
  "locality": { "id": 3723, "singleLine": "Broadbeach QLD 4218" },
  "street": { "id": 38135 }
}
Search key extractedlocalityId = 3723

All initial candidates must belong to Broadbeach, the exact Cotality locality represented by ID 3723.

Step 1

Address suggestion → property ID

The address search endpoint returns a validated CoreLogic property ID.

Step 2

Property ID → location record

The location endpoint supplies canonical locality, street and postcode identifiers.

Step 3

location.locality.id → candidate input

The nested value 3723 becomes the geographic input to both candidate endpoints.

02 / retrieve local candidate summaries

Two endpoints, one exact locality.

The application calls both sale and rental search. These APIs operate inside the named locality and do not include neighbouring localities.

On-market sale candidates

Request input: locality ID 3723.

GET /search/au/property/locality/3723/otmForSale

Live API response: page 0 · 20 records per page · 8,656 total records reported.

On-market rental candidates

Request input: locality ID 3723.

GET /search/au/property/locality/3723/otmForRent

Live API response: page 0 · 20 records per page · 58 total records reported.

Current page size

The backend sends no page-size parameter. Cotality returns the default first page: 20 sale summaries and 20 rental summaries. The initial merged pool is therefore up to 40 records.

04 / select before enriching

Do the economical work first.

Candidate summaries are fast but can be incomplete. Parcel Atlas removes non-useful records, does an inexpensive configuration pre-score, then calls deeper APIs for the strongest candidates.

StageRuleResult for Broadbeach example
1. MergeCombine sale and rental first pages.Up to 40 candidates

05 / final match calculation

A transparent 100-point score.

The score is property similarity, not a valuation, ranking or tenant assessment. A missing attribute receives no points rather than an assumed match.
